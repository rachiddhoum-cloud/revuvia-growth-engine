# Sprint 3 — Growth Operating System (Founder OS)

The pipeline from Sprint 2 produces content. The Growth Operating System turns
that content into **traffic, leads, revenue, and MRR** — the four KPIs the
founder actually watches. This sprint ships a complete operating rhythm: daily
brief, weekly action plan, sales/seo/content command centers, and a weekly CEO
report, all generated by cron and persisted to Postgres.

## 1. Architecture

```
supabase (source of truth)
  ├── daily_metrics / page_metrics   → traffic & revenue
  ├── content_items / generation_runs → pipeline output & AI cost
  ├── customers (status, mrr_usd)    → MRR & churn
  └── prospects (priority, probability, recommended_message, follow_up_at)
        │
        ▼
src/lib/ops/load.ts (server-only) → GrowthSnapshot (weekly window, local-timezone safe)
        │
        ▼
Pure generators (deterministic, unit-tested, stores injected)
  ├── ops/ice.ts             ICE score (impact × confidence × ease, max 1000)
  ├── ops/snapshot.ts        weekly aggregation + SEO traffic estimate
  ├── ops/seo-missions.ts    traffic losses, under-linked pages, keyword attacks, competitor gaps
  ├── ops/sales.ts           scoring (priority 0-100), industry messaging, follow-up dates
  ├── ops/content-queue.ts   ranked ideas with AI cost (USD 0.02/1k words)
  ├── ops/plan.ts            TOP 10 merged actions (P0/P1/P2) + MRR forecast
  ├── ops/brief.ts           founder daily brief (< 3 min read)
  └── ops/ceo-report.ts      weekly report: markdown + print-ready HTML (A4)
        │
        ▼
Persisted idempotently → reports (owner_id, type, period_start) — upsert
```

Routes (cron, protected by `x-cron-secret` = `CRON_SECRET`):

| Route | Artifact | Schedule (vercel.json) |
| --- | --- | --- |
| `POST /api/ops/plan` | weekly action plan | `0 6 * * 1` (Mon 06:00) |
| `POST /api/ops/brief` | daily brief | `0 7 * * *` (daily 07:00) |
| `POST /api/ops/report` | weekly CEO report | `0 8 * * 1` (Mon 08:00) |

All three share one implementation (`src/lib/ops/generate.ts`); the routes only
pick the artifact and the owner (`ownerId`, default `"system"`).

## 2. Execution flow (weekly rhythm)

1. **Sunday night** — `customers` and `prospects` updated (sales adds/edits rows).
2. **Monday 06:00** — action plan generated: 3 centers (sales, SEO, content)
   scored by ICE, merged, top 10 kept, each with `mrrImpactUsd`.
3. **Monday 08:00** — CEO report persisted (markdown + `pdf_ready` HTML),
   revenue forecast, pipeline summary, roadmap for next week.
4. **Every morning 07:00** — daily brief: today's priorities, new
   opportunities, urgent issues.
5. **All day** — CEO Dashboard (`/dashboard`) renders the latest snapshot and
   plan; each action shows impact, effort, ICE, and MRR impact.

## 3. Business value

- **Founder bandwidth**: the brief is a 3-minute read; decisions, not research.
- **Revenue focus**: every generated action carries an estimated `mrrImpactUsd`;
  the plan is ranked by ICE, not by recency.
- **Sales follow-up**: prospects get a `recommended_message` (industry-tuned:
  café/restaurant/salon/dentist/generic), `follow_up_at`, and probability so no
  deal goes cold.
- **Cost transparency**: content queue shows `aiCostUsd` per idea
  (≈ USD 0.02/1k words), so the plan fits a budget.
